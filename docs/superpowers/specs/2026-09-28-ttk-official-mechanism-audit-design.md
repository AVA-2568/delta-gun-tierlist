## 1. 目标与判定标准

验证项目核心 TTK 计算(`(E[N] − 1) × 射击间隔`)是否符合《三角洲行动》烽火地带官方机制,分三层:

| 层 | 判定标准 |
| :-- | :-- |
| L1 本地逐位 | 代码重算 E[N] 与 dfttk v3 `candidateMetrics` 一致;射击间隔与 `reference_candidates` 一致;精度以真实重跑结果为准,不以文档声称为准 |
| L2 机制对照 | `ballistics.py` 8 条伤害规则、`curves.py` 机制曲线、`weapon_state.py` 面板映射,与官方/社区公认游戏机制逐条对照,无矛盾项 |
| L3 口径与自洽 | 0–80m 距离场(官方 `distanceRange`)、E[N] 数学期望定义、四项排除(开镜/初速/换弹/命中率)与官方排行口径一致;README「3774 零偏差」/ llms.txt「3774 99.92%」/ ballistics.py「16 样本逐位」三处表述裁定统一 |

## 2. 执行架构(两路并行子代理)

- **子代理 A(本地复核)**:盘点并重跑验证基础设施(`tests/test_ballistics.py`、`tests/test_data_integrity.py`、`data/game/validation_samples.json`);重算 E[N] 全量对比 `candidateMetrics`;核对射击间隔验证(291 候选零偏差声称);L3 口径三侧(代码/文档/数据)一致性。只读产品代码与数据,不改任何项目文件。
- **子代理 B(外部对照)**:检索官方+社区公认机制(血量/hitbox 倍率/碎甲/护甲覆盖/距离衰减/命中分布/射击间隔),逐条对照 `ballistics.py` 8 条规则与引擎实现。来源优先级:官方公告/官网 > dfttk/moligod 等社区工具 > 攻略组;逐条标注来源与可信度。
- **主线程**:交叉汇总、冲突仲裁(本地逐位一致但外部资料矛盾 → 标注「上游数据层疑点」而非代码 bug)、写审计报告。

## 3. 报告结构

## 4. 错误处理

- 验证脚本缺失/不可复跑 → 子代理 A 重建最小复现脚本(临时证据,置于临时目录,不入库)。
- web 源冲突 → 官方来源优先,冲突如实入报告。
- 外部资料不足 → 如实标注「无公开资料佐证」,不臆断。

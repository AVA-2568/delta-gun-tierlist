# ADR-0001：TTK 口径以引擎为准（含首发扳机延迟与弹丸飞行时间）

- 状态：已接受
- 日期：2026-10-18
- 决策人：YH
- 影响面：README、`docs/榜单/*.md`、`llms.txt`、`docs/superpowers/specs/2026-09-20-pure-ttk-redesign-design.md`、渲染层

## 背景

`src/engine/engagement.py` 的 `ttk_at()` 实际计算：

```
实战 TTK = 首发扳机延迟 + 第 E 发击发时刻 + 弹丸飞行时间
```

而 README、24 份距离榜文档、`llms.txt` 与设计规范 v3.1 均声明「不含弹丸飞行时间」，
排序键写作 `(E − 1) × 射击间隔`。

实测证据（M4A1，5 级弹，5-5 情景，本体裸枪）：

| 距离 | 实战 TTK | 其中飞行时间 |
| --: | --: | --: |
| 0 m | 388.39 ms | 0.00 ms |
| 80 m | 724.41 ms | 139.13 ms |

以 5-5 情景本体裸枪粗算 50–80 m：剔除飞行时间后，T0 七席更换 6 席
（进入：复合弓、AS-Val、VSS；退出：Mini-14、RM277、M14）。

结论：这不是文案瑕疵，而是会改变分层结果的实质口径分叉。

## 决策

以引擎为准，对外统一声明：

```
实战 TTK = 首发扳机延迟 + 击发时刻 + 弹丸飞行时间
```

- **击发时刻**：单发/全自动为 `(E[N] − 1) × 射击间隔`；连发武器按官方 `sdkTiming`
  节拍计算；多弹丸武器按扣动扳机发数（`弹丸数 / 有效弹丸数`）计算。
- **弹丸飞行时间**：`距离 / 原始初速`，使用不含精校修正的原始初速。
- **「纯 TTK」的定义**：榜单只按 TTK 排序，不合成经济性、操控性等权重；
  **不表示**剔除飞行时间。

## 后果

1. 渲染层把公式收敛为**唯一常量**，README 与 24 份距离榜从同一常量生成。
2. `llms.txt` 与设计规范同步修订，删除「不含弹丸飞行时间」的表述。
3. 新增测试：README 与每份距离榜必须出现规范公式，且不得出现「不含弹丸飞行时间」。
4. 引擎与数据不变，**无需全量重算**；仅需重渲染文档。
5. 今后任何口径变更必须新增 ADR 并全量重算，禁止只改文案。

## 否决的方案

| 方案 | 否决理由 |
| :-- | :-- |
| 以文档为准（剔除飞行与延迟） | 与官方 dfttk 默认口径分叉；80 m 处 139 ms 是真实存在的击杀耗时，剔除后榜单不再回答「击杀要多久」 |
| 双口径并存 | 列数与解释成本最高；两套排序并存会产生「哪套算数」的歧义 |

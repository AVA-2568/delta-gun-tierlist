# ADR-0005：删除 `--all` 模式，仓库只发布 6 个默认情景

- 状态：已接受
- 日期：2026-10-18
- 决策人：YH
- 影响面：`src/pipeline.py`、README 情景索引、相关测试

## 背景

`python -m src.pipeline --all` 会计算官方 21 个情景（7 组甲弹 × 3 种命中分布）加修脚，
在仓库根写出 22 份榜单 JSON（约 19 MB）与 88 份距离榜文档。

但每日 CI 只维护 `DEFAULT_SCENARIOS`（6 个）。两者不一致导致：

- 本地跑过一次 `--all` 后，仓库里多出 16 份无人维护的榜单；
- 次日 CI 只刷新 6 份，另外 16 份停在旧数据；
- CI 重生成 README 时索引只列 6 个，那 16 份的链接消失，文件却仍在仓库里，
  读者从旧链接或搜索进入会看到过期数据。

## 决策

删除 `--all` 参数与 `all_scenarios` 分支。发布集合固定为 `DEFAULT_SCENARIOS`：

| 情景 | 护甲 | 弹药 | 命中分布 |
| :-- | --: | --: | :-- |
| 护甲4弹药4-实战 | 4 | 4 | `default` |
| 护甲4弹药5-实战 | 4 | 5 | `default` |
| 护甲5弹药4-实战 | 5 | 4 | `default` |
| 护甲5弹药5-实战（主榜） | 5 | 5 | `default` |
| 护甲6弹药5-实战 | 6 | 5 | `default` |
| 修脚 | — | 3/4/5 | `legs-only` |

单情景仍可用 `--scenario <完整 ID>` 计算；产物写到 `--output-dir` 指定的目录，
不会进入正式榜单集合。

## 后果

- `run_pipeline` / `refresh_prices` / `check_stale` 删除 `all_scenarios` 参数，
  目标集合规则统一为「显式 scenarios 优先，否则 DEFAULT_SCENARIOS」。
- README 删除「用 `--all` 可生成全部情景」的说明。
- 仓库不再出现 22 情景产物；官方其余 16 个情景（含 `center` / `chest-only`
  理论聚焦预设）不随仓库发布。

## 否决的方案

| 方案 | 否决理由 |
| :-- | :-- |
| 正式发布 22 个情景 | 每日多写约 19 MB JSON 与 88 份文档，渲染与仓库体积成本过高 |
| 保留 `--all` 作为本地分析模式 | 仍可能在仓库根误执行并污染发布集合；需要额外的目录护栏，收益不抵成本 |

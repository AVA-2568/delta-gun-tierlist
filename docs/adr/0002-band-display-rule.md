# ADR-0002：距离榜展示规则（T0 全列 + T1 前 100）

- 状态：已接受
- 日期：2026-10-18
- 决策人：YH
- 影响面：`src/renderers/ttk_report.py`、README、24 份距离榜文档、`tests/test_renderers.py`

## 背景

`render_band_doc(limit=120)` 用一个未命名的 120 行上限过滤展示行，而页头声称
「只列 T0 / T1」。实际数据：

| 情景 | 每带 T0 | 每带 T1 | T0+T1 |
| :-- | --: | --: | --: |
| 主榜（5-5） | 50 | 83 | 133 |
| 修脚 | 150 | 248 | 398 |

后果：主榜每带静默丢掉 13 行 T1；修脚每带丢掉 278 行，占 T0/T1 的 70%。
页头没有任何截断提示，读者会误以为看到的是全部 T0/T1。

另外，页头「空号即其间存在未列出行」也不成立：层级按 TTK 单调切分，
展示行的排名必然连续，不存在空号。

## 决策

展示规则改为**按层级分配预算**：

1. **T0 全列**，不截断。
2. **T1 只列全量排名前 100 行**（`T1_DISPLAY_LIMIT = 100`）。
3. 页头必须写明实际数量与截断：
   `T0 共 X 行（全列）；T1 共 Y 行，列前 min(Y, 100) 行；其余见 data/榜单/<情景>.json`。
4. 删除「空号即存在未列出行」的表述，改为「未列出的行排名均在本表末行之后」。

## 后果

- 主榜：每带 50 + 83 = 133 行，T1 全展示（83 < 100）。
- 修脚：每带 250–252 行（T0 150–152 + T1 前 100），T1 隐藏 145–148 行。页面变长是已知代价。
- README 的分层说明同步改为上述规则，不再写「只列 T0 / T1」。
- 新增测试：构造 T0=3、T1=150 的 payload，断言 T0 全在、T1 恰好 100 行、
  页头包含真实数量与截断说明。
- 仅重渲染，无需重算 TTK。

## 否决的方案

| 方案 | 否决理由 |
| :-- | :-- |
| 保留 120 行上限 + 明示截断 | 120 无业务含义；会切掉 T1 尾部，却保留部分 T1 头部，规则不自洽 |
| 全列 T0/T1 | 修脚 398 行，阅读与渲染成本过高 |
